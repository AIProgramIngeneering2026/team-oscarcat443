# ADR 0001. Один процесс для API, Job и проверки SLA

- Дата: 2026-11-15
- Статус: принято

## Контекст и ограничения

Oscar SLA Monitoring — учебный сервис одной команды поддержки. В первой версии нет нескольких организаций и нет отдельного контура «чужих» клиентов. Нужны HTTP API, жизненный цикл Job, два Tool и один внешний сервис уведомлений. Срок практик требует поднять систему из чистого клона одной командой. Отдельные сервисы на API, SLA и уведомления увеличат число репозиториев и соглашений сверх скелета заявки.

## Решение

API, сценарии инцидента, Dispatcher, Registry, оба Tool, планировщик SLA и адаптер уведомлений работают в одном процессе ASP.NET Core. PostgreSQL остаётся отдельным процессом, как хранилище из заявки. Доступ к инциденту по неизвестному id отвечает `404 job_not_found` и не сообщает, существует ли запись в другом контуре: другого контура нет.

## Рассмотренные альтернативы

1. Три сервиса: API, планировщик SLA, отправка уведомлений. Отвергнуто: появляется сеть между своими частями раньше, чем есть вторая независимая нагрузка.
2. Отдельный сервис на каждый Tool. Отвергнуто: заявка требует добавлять Tool без правки Dispatcher, для этого хватает `ITool` и `ToolRegistry` внутри процесса.

## Цена решения

Планировщик и API делят процесс и пул соединений с PostgreSQL. Долгая проверка SLA может увеличить время ответа API. Падение процесса останавливает и приём инцидентов, и эскалацию до следующего запуска.

## Условия пересмотра

Решение пересматривается, если фоновая проверка SLA регулярно задерживает ответ `POST /jobs` дольше согласованного предела либо появляется второй независимый экземпляр API.
